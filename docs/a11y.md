# Accessibility (WCAG 2.2 AA) — as-built evidence

## 1. Foundations

- **Bilingual RTL/LTR**: `<html lang dir>` defaults are AR/RTL; the shell root re-asserts `lang`, `dir` and logical CSS (`ms-*/me-*/ps-*/pe-*`, `text-start`) everywhere. No hard-coded left/right in layout CSS.
- **Keyboard operability**: every interactive control is a native `button`/`a`/`input`; dialogs (Radix) trap focus and restore it on close; the path's locked lessons stay focusable and open a prerequisite dialog instead of being disabled-with-no-explanation.
- **Visible focus**: default Tailwind focus rings kept (`focus-visible:ring-*` tokens in `globals.css`); no `outline: none` anywhere.
- **Skip link**: `<a href="#main">` skip link is the first focusable element in the shell; `main#main` is the target.

## 2. Live regions (screen-reader lab results)

- `RunPanel` output: `role="status" aria-live="polite"` — run results announce as they stream.
- Exercise test rows: `aria-live="polite"` on the results block — pass/fail announcements without focus stealing.
- Lesson completion + hint reveals: polite live text (e.g. hint cost note, reflect saved note).
- The console pane carries `aria-label` (localized) + `aria-live="polite"`.

## 3. Reduced motion

- `prefers-reduced-motion` is honored by default (matched at shell mount, `data-reduce-motion` on the root) and overridable in Settings.
- The attribute gates the CSS animation set (`gentle-rise`, pulse, transitions) — one mechanism, no per-component toggles.
- The step-through visualizer is inherently step-based (manual stepping is the reduced-motion alternative to autoplay).

## 4. Color & contrast

- Semantic tokens (`--color-success`, muted-foreground, border) in `src/styles/tokens.css`; meaning is never carried by color alone (locked lessons show a lock icon AND label; test rows show name + expected/actual text, not just a tint).
- Dark/sepia/light themes all pass AA body-text contrast (token pairs audited in the M5 pass; the warm-dark palette was chosen for ≥ 4.5:1 body text).

## 5. Visualizer & charts

- All visualizers ship a textual step narration (trace steps list variables/line) — the text alternative is the primary interface, not an afterthought (R-ARC-08).
- Coverage/progress numbers are real text (tables/percent strings), not images.

## 6. Content authoring

- Bilingual `alt`-style requirements live in the schema: visual-free lessons (pure text + code) keep the visualizer textual; exercise diagrams are ASCII/text-first.
- `reviewed: { content, ar, en, a11y }` status tracked in PROGRESS per milestone batch.

## 7. Automated checks & manual checklist

- ESLint `jsx-a11y` rules run in `bun run lint` (0 errors at M5).
- Manual checklist (per release): keyboard-only walkthrough of dashboard → lesson → run code → submit → hint ladder → complete; RTL+LTR screenshots light/dark; screen-reader smoke test of run results and test outcomes on at least one lesson per track.
- Known gap (tracked): a full axe-CI integration is not yet wired into the build; the lint rules + manual checklist cover the shipped surfaces (recorded honestly per M1 note).
