# ADR-0002 — In-browser Python runtime
**Context:** R-LAB-01 mandates browser Python (WASM) in a Web Worker, never main thread, with time/memory guards.
**Decision:** Pyodide pinned to exact version **0.29.5**, self-hosted from a versioned path `public/vendor/pyodide/0.29.5/` (vendored dist). The loader's source ladder is local → (purge Cache Storage) local → the **same pinned version** from the official jsDelivr dist (`https://cdn.jsdelivr.net/pyodide/v0.29.5/full/`, already documented in `src/lib/runtime/protocol.ts`) as a bounded last-resort fallback; CSP allows that one origin for this purpose and nothing else. The version segment in the URL guarantees a stale service-worker/browser cache can never mix files from two Pyodide builds — the classic "Program terminated with exit(1)" production failure. Runs in a dedicated classic Worker (`public/pyodide-worker.js`). Per-run time limit 10s default, enforced by a **per-run watchdog that hard-terminates the worker and respawns lazily on the next run** (the only reliable interrupt without `SharedArrayBuffer`; COOP/COEP were deliberately NOT adopted — they would break the sandbox routing of ADR-0007 and offer no benefit over terminate+respawn here). stdout/stderr captured and relayed as worker events. `sqlite3` is vendored as a pinned wheel from the same 0.29.5 dist, sha256-verified against `pyodide-lock.json`, and FS-preloaded together with `public/py-modules/minigrad.py` (M3, ADR-0008).
**M5 correction note (2026-10-19):** the original text of this ADR said "0.28.x" and mentioned a `SharedArrayBuffer` interrupt flag and matplotlib-canvas rendering. Reality shipped differently and this revision records the as-built truth at M5: 0.27.7, watchdog terminate+respawn (zero `SharedArrayBuffer` references in the worker), and no vendored matplotlib — the plotting chapters (D2L) teach with pure-Python numeric exercises instead; an unvendored matplotlib would violate R-ARC-09's no-unaudited-origins bar. Version pinning policy: bump the wheel + `pyodide-lock.json` together, re-run the Pyodide regression harness (`scripts/test_pyodide_minigrad.ts`), then re-verify one lesson E2E.
**M6 upgrade note (2026-10-21):** upgraded the pin to **0.29.5** (Python 3.13.2). Root cause: Pyodide 0.27.x cannot boot on current Chromium (reproduced on Chromium 140: every 0.27.x payload — self-hosted or official CDN — aborts at `init_fs_encoding` with `LookupError: no codec search functions registered`, surfacing as "loadPyodide failed: Program terminated with exit(1)"). 0.28.0+ and Firefox boots 0.27.x fine, confirming a dist/runtime incompatibility rather than a serving bug. All bytes were verified: the vendored stdlib hashed identical to jsDelivr and contained 554 entries (including `encodings`). The E2E run test now asserts the worked example's real stdout (`مرحبًا! أنا بايثون` / `5`), because asserting "a `<pre>` exists" previously masked a failed boot.
**Consequences:** Tier A covers PY4E ch1–16 fully; ML/NN lessons use our NumPy-free scalar autograd (M3, ADR-0008) — not scikit-learn/torch.
