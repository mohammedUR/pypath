# i18n guide (AR/EN)

## 1. Model

- **Arabic is the default and the reference.** `src/lib/i18n/ar.ts` is the reference dictionary (`as const`); `en.ts` must mirror its **keys exactly** (values differ, obviously). The shared type is `Dict = Stringify<typeof ar>` — key parity is enforced by TypeScript; value parity is meaningless.
- `translate(locale, key, vars)` walks the dot path, falls back to the other locale, then to the raw key — the UI never crashes on a missing key, but CI treats new UI keys as a review item.
- `{placeholder}` interpolation is locale-agnostic; Arabic strings embed Latin numerals/identifiers directly (بايثون, Kaggle).

## 2. Locale & direction

- `useI18nStore` (localStorage `pypath.i18n`) holds the locale; default `ar`.
- The hash carries the locale: `#/ar/...` / `#/en/...`. `useRouterSync` keeps the store in lockstep with the hash — deep links now land in the right language on first paint of the client (M5 fix; the in-app toggle was always correct).
- Direction: `dir` is derived from locale (`ar → rtl`) and set on the shell root (and `<html>` default in layout). All layout CSS uses logical properties (`ms/me/ps/pe/start/end`) so one stylesheet serves both directions.
- Arabic numerals: XP renders `toLocaleString('ar-EG')` in Arabic, `en` in English (dashboard).

## 3. Content vs UI

- UI strings live in the dictionaries; **lesson content is bilingual data** (`{ ar, en }` fields) inside the lesson files, picked at render time by `pick()`. There is no runtime machine translation (prohibited, §17) — every Arabic string is authored by hand.
- Terminology glossary: `بايثون` (never بيثون), `باي تورش`, `الشبكة العصبية`, `الموتر`/tensor on first mention with the Latin term in parentheses. Uncertain terms are flagged `review: needed` per OQ-8 (list maintained in `docs/OPEN-QUESTIONS.md`).

## 4. Arabic style rules (enforced by the M5 pass)

1. Tanwin fath is written **before** the seat alef: `دائمًا`, `أبدًا`, `مثلًا`, `أيضًا`, `تلقائيًا` (the corpus is 93% this convention — it is now 100%).
2. No bare adverbs without tanwin (`دائما` → `دائمًا`).
3. `بـ` kashida before Latin identifiers: `بـ open`, `الـ ?`.
4. Rhetorical doubling is fine (`سطرًا سطرًا`), accidental duplication is not (`إلى إلى` was a real bug found and fixed).
5. Scanner: `python3 scripts/m5_arabic_scan2.py` — rerun after bulk edits.

## 5. Adding a UI string

1. Add the key to `ar.ts` (reference) and `en.ts` (same path).
2. `bunx tsc --noEmit` fails if keys diverge — that's the parity gate.
3. Use `t('section.key', { vars })` in the component; never concatenate locale sentences in code.
