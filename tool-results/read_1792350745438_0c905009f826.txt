   146→1.2 Key Components
   147→In our wake word example, we described a dataset consisting of audio snippets and binary
   148→labels, and we gave a hand-wavy sense of how we might train a model to approximate a
   149→mapping from snippets to classifications. This sort of problem, where we try to predict a
   150→designated unknown label based on known inputs given a dataset consisting of examples
   151→for which the labels are known, is called supervised learning. This is just one among many
   152→kinds of machine learning problems. Before we explore other varieties, we would like to
   153→shed more light on some core components that will follow us around, no matter what kind
   154→of machine learning problem we tackle:
   155→1. The data that we can learn from.
   156→2. A model of how to transform the data.
   157→3. An objective function that quantifies how well (or badly) the model is doing.
   158→4. An algorithm to adjust the model’s parameters to optimize the objective function.

   163→1.2.1 Data
   164→It might go without saying that you cannot do data science without data. We could lose
   165→hundreds of pages pondering what precisely data is, but for now, we will focus on the key
   166→properties of the datasets that we will be concerned with. Generally, we are concerned with
   167→a collection of examples. In order to work with data usefully, we typically need to come
   168→up with a suitable numerical representation. Each example (or data point, data instance,
   169→sample) typically consists of a set of attributes called features (sometimes called covariates
   170→or inputs), based on which the model must make its predictions. In supervised learning
   171→problems, our goal is to predict the value of a special attribute, called the label (or target),
   172→that is not part of the model’s input.
   173→If we were working with image data, each example might consist of an individual photo-
   174→graph (the features) and a number indicating the category to which the photograph belongs
   175→(the label). The photograph would be represented numerically as three grids of numerical
   176→values representing the brightness of red, green, and blue light at each pixel location. For
   177→example, a 200 × 200 pixel color photograph would consist of 200 × 200 × 3 = 120000
   178→numerical values.
   179→Alternatively, we might work with electronic health record data and tackle the task of pre-
   180→dicting the likelihood that a given patient will survive the next 30 days. Here, our features
   181→might consist of a collection of readily available attributes and frequently recorded mea-
   182→surements, including age, vital signs, comorbidities, current medications, and recent pro-
   183→cedures. The label available for training would be a binary value indicating whether each
   184→patient in the historical data survived within the 30-day window.
   185→In such cases, when every example is characterized by the same number of numerical fea-
   186→tures, we say that the inputs are fixed-length vectors and we call the (constant) length of
   187→the vectors the dimensionality of the data. As you might imagine, fixed-length inputs can
   188→be convenient, giving us one less complication to worry about. However, not all data can
   189→easily be represented as fixed-length vectors. While we might expect microscope images to
   190→come from standard equipment, we cannot expect images mined from the Internet all to have
   191→the same resolution or shape. For images, we might consider cropping them to a standard
   192→size, but that strategy only gets us so far. We risk losing information in the cropped-out
   193→portions. Moreover, text data resists fixed-length representations even more stubbornly.
   194→Consider the customer reviews left on e-commerce sites such as Amazon, IMDb, and Tri-
   195→pAdvisor. Some are short: “it stinks!”. Others ramble for pages. One major advantage of
   196→deep learning over traditional methods is the comparative grace with which modern models
   197→can handle varying-length data.
   198→Generally, the more data we have, the easier our job becomes. When we have more data, we
   199→can train more powerful models and rely less heavily on preconceived assumptions. The
   200→regime change from (comparatively) small to big data is a major contributor to the success
   201→of modern deep learning. To drive the point home, many of the most exciting models in
   202→deep learning do not work without large datasets. Some others might work in the small
   203→data regime, but are no better than traditional approaches.
   204→Finally, it is not enough to have lots of data and to process it cleverly. We need the right

   222→1.2.2 Models
   223→Most machine learning involves transforming the data in some sense. We might want to
   224→build a system that ingests photos and predicts smiley-ness. Alternatively, we might want to
   225→ingest a set of sensor readings and predict how normal vs. anomalous the readings are. By
   226→model, we denote the computational machinery for ingesting data of one type, and spitting
   227→out predictions of a possibly different type. In particular, we are interested in statistical
   228→models that can be estimated from data. While simple models are perfectly capable of ad-
   229→dressing appropriately simple problems, the problems that we focus on in this book stretch
   230→the limits of classical methods. Deep learning is differentiated from classical approaches
   231→principally by the set of powerful models that it focuses on. These models consist of many
   232→successive transformations of the data that are chained together top to bottom, thus the
   233→name deep learning. On our way to discussing deep models, we will also discuss some
   234→more traditional methods.
   235→1.2.3 Objective Functions
   236→Earlier, we introduced machine learning as learning from experience. By learning here, we
   237→mean improving at some task over time. But who is to say what constitutes an improvement?
   238→You might imagine that we could propose updating our model, and some people might
   239→disagree on whether our proposal constituted an improvement or not.
   240→In order to develop a formal mathematical system of learning machines, we need to have
   241→formal measures of how good (or bad) our models are. In machine learning, and optimiza-
   242→tion more generally, we call these objective functions. By convention, we usually define
   243→objective functions so that lower is better. This is merely a convention. You can take any
   244→function for which higher is better, and turn it into a new function that is qualitatively iden-
   245→tical but for which lower is better by flipping the sign. Because we choose lower to be
   246→better, these functions are sometimes called loss functions.
   247→When trying to predict numerical values, the most common loss function is squared error,
   248→i.e., the square of the difference between the prediction and the ground truth target. For
   249→classification, the most common objective is to minimize error rate, i.e., the fraction of
   250→

   254→examples on which our predictions disagree with the ground truth. Some objectives (e.g.,
   255→squared error) are easy to optimize, while others (e.g., error rate) are difficult to optimize
   256→directly, owing to non-differentiability or other complications. In these cases, it is common
   257→instead to optimize a surrogate objective.
   258→During optimization, we think of the loss as a function of the model’s parameters, and treat
   259→the training dataset as a constant. We learn the best values of our model’s parameters by
   260→minimizing the loss incurred on a set consisting of some number of examples collected for
   261→training. However, doing well on the training data does not guarantee that we will do well
   262→on unseen data. So we will typically want to split the available data into two partitions:
   263→the training dataset (or training set), for learning model parameters; and the test dataset
   264→(or test set), which is held out for evaluation. At the end of the day, we typically report
   265→how our models perform on both partitions. You could think of training performance as
   266→analogous to the scores that a student achieves on the practice exams used to prepare for
   267→some real final exam. Even if the results are encouraging, that does not guarantee success
   268→on the final exam. Over the course of studying, the student might begin to memorize the
   269→practice questions, appearing to master the topic but faltering when faced with previously
   270→unseen questions on the actual final exam. When a model performs well on the training set
   271→but fails to generalize to unseen data, we say that it is overfitting to the training data.
   272→1.2.4 Optimization Algorithms
   273→Once we have got some data source and representation, a model, and a well-defined objec-
   274→tive function, we need an algorithm capable of searching for the best possible parameters
   275→for minimizing the loss function. Popular optimization algorithms for deep learning are
   276→based on an approach called gradient descent. In brief, at each step, this method checks
   277→to see, for each parameter, how that training set loss would change if you perturbed that
   278→parameter by just a small amount. It would then update the parameter in the direction that
   279→lowers the loss.

   393→classifier, whose output is the predicted class assignment.

   395→mize a model that can only output a firm categorical assignment, e.g., either “cat” or “dog”.

   397→ties. Given features of an example, our model assigns a probability to each possible class.

   483→In the field of information retrieval, we often impose ranks on sets of items. Take web

   485→query, but rather which, among a set of relevant results, should be shown most prominently

   491→used PageRank to prioritize the more authoritative pages. Nowadays, search engines use
