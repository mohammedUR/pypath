     5→Before we worry about making our neural networks deep, it will be helpful to implement
     6→some shallow ones, for which the inputs connect directly to the outputs. This will prove im-
     7→portant for a few reasons. First, rather than getting distracted by complicated architectures,
     8→we can focus on the basics of neural network training, including parametrizing the output
     9→layer, handling data, specifying a loss function, and training the model. Second, this class
    10→of shallow networks happens to comprise the set of linear models, which subsumes many
    11→classical methods of statistical prediction, including linear and softmax regression. Un-
    12→derstanding these classical tools is pivotal because they are widely used in many contexts
    13→and we will often need to use them as baselines when justifying the use of fancier archi-
    14→tectures. This chapter will focus narrowly on linear regression and the next one will extend
    15→our modeling repertoire by developing linear neural networks for classification.
    16→3.1 Linear Regression
    17→Regression problems pop up whenever we want to predict a numerical value. Common ex-
    18→amples include predicting prices (of homes, stocks, etc.), predicting the length of stay (for
    19→patients in the hospital), forecasting demand (for retail sales), among numerous others. Not
    20→every prediction problem is one of classical regression. Later on, we will introduce classifi-
    21→cation problems, where the goal is to predict membership among a set of categories.
    22→As a running example, suppose that we wish to estimate the prices of houses (in dollars)
    23→based on their area (in square feet) and age (in years). To develop a model for predicting
    24→house prices, we need to get our hands on data, including the sales price, area, and age for
    25→each home. In the terminology of machine learning, the dataset is called a training dataset
    26→or training set, and each row (containing the data corresponding to one sale) is called an
    27→example (or data point, instance, sample). The thing we are trying to predict (price) is
    28→called a label (or target). The variables (age and area) upon which the predictions are
    29→based are called features (or covariates).

    43→3.1.1 Basics
    44→Linear regression is both the simplest and most popular among the standard tools for tack-
    45→ling regression problems. Dating back to the dawn of the 19th century (Gauss, 1809, Leg-
    46→endre, 1805), linear regression flows from a few simple assumptions. First, we assume that
    47→the relationship between features x and target 𝑦is approximately linear, i.e., that the con-
    48→ditional mean 𝐸[𝑌| 𝑋= x] can be expressed as a weighted sum of the features x. This
    49→setup allows that the target value may still deviate from its expected value on account of
    50→observation noise. Next, we can impose the assumption that any such noise is well behaved,
    51→following a Gaussian distribution. Typically, we will use 𝑛to denote the number of exam-
    52→ples in our dataset. We use superscripts to enumerate samples and targets, and subscripts
    53→to index coordinates. More concretely, x(𝑖) denotes the 𝑖th sample and 𝑥(𝑖)
    54→𝑗

    57→Model
    58→At the heart of every solution is a model that describes how features can be transformed
    59→into an estimate of the target. The assumption of linearity means that the expected value of
    60→the target (price) can be expressed as a weighted sum of the features (area and age):
    61→price = 𝑤area · area + 𝑤age · age + 𝑏.
    62→(3.1.1)
    63→Here 𝑤area and 𝑤age are called weights, and 𝑏is called a bias (or offset or intercept). The
    64→weights determine the influence of each feature on our prediction. The bias determines the
    65→value of the estimate when all features are zero. Even though we will never see any newly-
    66→built homes with precisely zero area, we still need the bias because it allows us to express
    67→all linear functions of our features (rather than restricting us to lines that pass through the
    68→origin). Strictly speaking, (3.1.1) is an aﬀine transformation of input features, which is
    69→characterized by a linear transformation of features via a weighted sum, combined with a
    70→translation via the added bias. Given a dataset, our goal is to choose the weights w and
    71→the bias 𝑏that, on average, make our model’s predictions fit the true prices observed in the
    72→data as closely as possible.

    74→expressing models long-form, as in (3.1.1), is common. In machine learning, we usually
    75→work with high-dimensional datasets, where it is more convenient to employ compact lin-
    76→ear algebra notation. When our inputs consist of 𝑑features, we can assign each an index
    77→(between 1 and 𝑑) and express our prediction ˆ𝑦(in general the “hat” symbol denotes an
    78→estimate) as

   189→Minibatch Stochastic Gradient Descent
   190→Fortunately, even in cases where we cannot solve the models analytically, we can still of-
   191→ten train models effectively in practice. Moreover, for many tasks, those hard-to-optimize
   192→models turn out to be so much better that figuring out how to train them ends up being well
   193→worth the trouble.
   194→The key technique for optimizing nearly every deep learning model, and which we will
   195→call upon throughout this book, consists of iteratively reducing the error by updating the
   196→parameters in the direction that incrementally lowers the loss function. This algorithm is
   197→called gradient descent.
   198→The most naive application of gradient descent consists of taking the derivative of the loss
   199→function, which is an average of the losses computed on every single example in the dataset.
   200→In practice, this can be extremely slow: we must pass over the entire dataset before making
   201→a single update, even if the update steps might be very powerful (Liu and Nocedal, 1989).
   202→Even worse, if there is a lot of redundancy in the training data, the benefit of a full update
   203→is limited.
   204→The other extreme is to consider only a single example at a time and to take update steps
   205→based on one observation at a time. The resulting algorithm, stochastic gradient descent
   206→(SGD) can be an effective strategy (Bottou, 2010), even for large datasets. Unfortunately,
   207→SGD has drawbacks, both computational and statistical. One problem arises from the fact
   208→that processors are a lot faster multiplying and adding numbers than they are at moving data
   209→from main memory to processor cache. It is up to an order of magnitude more efficient
   210→to perform a matrix–vector multiplication than a corresponding number of vector–vector
   211→operations. This means that it can take a lot longer to process one sample at a time compared
   212→to a full batch. A second problem is that some of the layers, such as batch normalization
   213→(to be described in Section 8.5), only work well when we have access to more than one
   214→observation at a time.
   215→The solution to both problems is to pick an intermediate strategy: rather than taking a full
   216→batch or only a single sample at a time, we take a minibatch of observations (Li et al., 2014).
   217→The specific choice of the size of the said minibatch depends on many factors, such as the
   218→amount of memory, the number of accelerators, the choice of layers, and the total dataset
   219→size. Despite all that, a number between 32 and 256, preferably a multiple of a large power
   220→of 2, is a good start. This leads us to minibatch stochastic gradient descent.

   222→ing of a fixed number |B| of training examples. We then compute the derivative (gradient)

   929→3.3.4 Summary
   930→Data loaders are a convenient way of abstracting out the process of loading and manipu-
   931→lating data. This way the same machine learning algorithm is capable of processing many
   932→different types and sources of data without the need for modification. One of the nice things
   933→about data loaders is that they can be composed. For instance, we might be loading images
   934→and then have a postprocessing filter that crops them or modifies them in other ways. As
   935→such, data loaders can be used to describe an entire data processing pipeline.
   936→As for the model itself, the two-dimensional linear model is about the simplest we might
   937→encounter. It lets us test out the accuracy of regression models without worrying about
   938→having insufficient amounts of data or an underdetermined system of equations. We will
   939→put this to good use in the next section.
