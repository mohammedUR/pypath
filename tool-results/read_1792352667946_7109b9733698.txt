     5→Image data is represented as a two-dimensional grid of pixels, be the image monochro-
     6→matic or in color. Accordingly each pixel corresponds to one or multiple numerical values
     7→respectively. So far we have ignored this rich structure and treated images as vectors of
     8→numbers by flattening them, irrespective of the spatial relation between pixels. This deeply
     9→unsatisfying approach was necessary in order to feed the resulting one-dimensional vectors
    10→through a fully connected MLP.
    11→Because these networks are invariant to the order of the features, we could get similar
    12→results regardless of whether we preserve an order corresponding to the spatial structure
    13→of the pixels or if we permute the columns of our design matrix before fitting the MLP’s
    14→parameters. Ideally, we would leverage our prior knowledge that nearby pixels are typically
    15→related to each other, to build efficient models for learning from image data.
    16→This chapter introduces convolutional neural networks (CNNs) (LeCun et al., 1995), a
    17→powerful family of neural networks that are designed for precisely this purpose. CNN-
    18→based architectures are now ubiquitous in the field of computer vision. For instance, on the
    19→Imagnet collection (Deng et al., 2009) it was only the use of convolutional neural networks,
    20→in short Convnets, that provided significant performance improvements (Krizhevsky et al.,
    21→2012).
    22→Modern CNNs, as they are called colloquially, owe their design to inspirations from biol-
    23→ogy, group theory, and a healthy dose of experimental tinkering. In addition to their sample
    24→efficiency in achieving accurate models, CNNs tend to be computationally efficient, both
    25→because they require fewer parameters than fully connected architectures and because con-
    26→volutions are easy to parallelize across GPU cores (Chetlur et al., 2014). Consequently,
    27→practitioners often apply CNNs whenever possible, and increasingly they have emerged
    28→as credible competitors even on tasks with a one-dimensional sequence structure, such as
    29→audio (Abdel-Hamid et al., 2014), text (Kalchbrenner et al., 2014), and time series analy-
    30→sis (LeCun et al., 1995), where recurrent neural networks are conventionally used. Some
    31→clever adaptations of CNNs have also brought them to bear on graph-structured data (Kipf
    32→and Welling, 2016) and in recommender systems.
    33→First, we will dive more deeply into the motivation for convolutional neural networks. This
    34→is followed by a walk through the basic operations that comprise the backbone of all con-
    35→volutional networks. These include the convolutional layers themselves, nitty-gritty details
    36→including padding and stride, the pooling layers used to aggregate information across ad-

    48→7.1 From Fully Connected Layers to Convolutions
    49→To this day, the models that we have discussed so far remain appropriate options when we
    50→are dealing with tabular data. By tabular, we mean that the data consist of rows corre-
    51→sponding to examples and columns corresponding to features. With tabular data, we might
    52→anticipate that the patterns we seek could involve interactions among the features, but we
    53→do not assume any structure a priori concerning how the features interact.
    54→Sometimes, we truly lack the knowledge to be able to guide the construction of fancier
    55→architectures. In these cases, an MLP may be the best that we can do. However, for high-
    56→dimensional perceptual data, such structureless networks can grow unwieldy.
    57→For instance, let’s return to our running example of distinguishing cats from dogs. Say that
    58→we do a thorough job in data collection, collecting an annotated dataset of one-megapixel
    59→photographs. This means that each input to the network has one million dimensions. Even
    60→an aggressive reduction to one thousand hidden dimensions would require a fully connected
    61→layer characterized by 106×103 = 109 parameters. Unless we have lots of GPUs, a talent for
    62→distributed optimization, and an extraordinary amount of patience, learning the parameters
    63→of this network may turn out to be infeasible.
    64→A careful reader might object to this argument on the basis that one megapixel resolution
    65→may not be necessary. However, while we might be able to get away with one hundred
    66→thousand pixels, our hidden layer of size 1000 grossly underestimates the number of hid-
    67→den units that it takes to learn good representations of images, so a practical system will
    68→still require billions of parameters. Moreover, learning a classifier by fitting so many pa-
    69→rameters might require collecting an enormous dataset. And yet today both humans and
    70→computers are able to distinguish cats from dogs quite well, seemingly contradicting these
    71→intuitions. That is because images exhibit rich structure that can be exploited by humans
    72→and machine learning models alike. Convolutional neural networks (CNNs) are one cre-
    73→ative way that machine learning has embraced for exploiting some of the known structure
    74→in natural images.

    78→of the object in the image. Ideally, our system should exploit this knowledge. Pigs usually
    79→do not fly and planes usually do not swim. Nonetheless, we should still recognize a pig

    98→We can now make these intuitions more concrete by enumerating a few desiderata to guide
    99→our design of a neural network architecture suitable for computer vision:
   100→1. In the earliest layers, our network should respond similarly to the same patch, regardless
   101→of where it appears in the image. This principle is called translation invariance (or
   102→translation equivariance).
   103→2. The earliest layers of the network should focus on local regions, without regard for the
   104→contents of the image in distant regions. This is the locality principle. Eventually, these
   105→local representations can be aggregated to make predictions at the whole image level.
   106→3. As we proceed, deeper layers should be able to capture longer-range features of the
   107→image, in a way similar to higher level vision in nature.
   108→Let’s see how this translates into mathematics.

   289→7.1.5 Summary and Discussion
   290→In this section we derived the structure of convolutional neural networks from first prin-
   291→ciples. While it is unclear whether this was the route taken to the invention of CNNs, it
   292→is satisfying to know that they are the right choice when applying reasonable principles
   293→to how image processing and computer vision algorithms should operate, at least at lower
   294→levels. In particular, translation invariance in images implies that all patches of an image
   295→will be treated in the same manner. Locality means that only a small neighborhood of pix-
   296→els will be used to compute the corresponding hidden representations. Some of the earliest
   297→references to CNNs are in the form of the Neocognitron (Fukushima, 1982).
   298→A second principle that we encountered in our reasoning is how to reduce the number of
   299→parameters in a function class without limiting its expressive power, at least, whenever
   300→certain assumptions on the model hold. We saw a dramatic reduction of complexity as a
   301→result of this restriction, turning computationally and statistically infeasible problems into
   302→tractable models.
   303→Adding channels allowed us to bring back some of the complexity that was lost due to the re-
   304→strictions imposed on the convolutional kernel by locality and translation invariance. Note
   305→that it is quite natural to add channels other than just red, green, and blue. Many satellite
   306→images, in particular for agriculture and meteorology, have tens to hundreds of channels,
   307→generating hyperspectral images instead. They report data on many different wavelengths.
   308→In the following we will see how to use convolutions effectively to manipulate the dimen-
   309→sionality of the images they operate on, how to move from location-based to channel-based
   310→representations, and how to deal with large numbers of categories efficiently.

   557→7.2.5 Cross-Correlation and Convolution
   558→Recall our observation from Section 7.1 of the correspondence between the cross-correlation
   559→and convolution operations. Here let’s continue to consider two-dimensional convolutional
   560→layers. What if such layers perform strict convolution operations as defined in (7.1.6) in-
   561→stead of cross-correlations? In order to obtain the output of the strict convolution operation,
   562→we only need to flip the two-dimensional kernel tensor both horizontally and vertically, and
   563→then perform the cross-correlation operation with the input tensor.
   564→It is noteworthy that since kernels are learned from data in deep learning, the outputs of
   565→convolutional layers remain unaffected no matter such layers perform either the strict con-
   566→volution operations or the cross-correlation operations.
   567→To illustrate this, suppose that a convolutional layer performs cross-correlation and learns
   568→the kernel in Fig. 7.2.1, which is here denoted as the matrix K. Assuming that other con-
   569→ditions remain unchanged, when this layer instead performs strict convolution, the learned
   570→kernel K′ will be the same as K after K′ is flipped both horizontally and vertically. That
   571→is to say, when the convolutional layer performs strict convolution for the input in Fig.
   572→7.2.1 and K′, the same output in Fig. 7.2.1 (cross-correlation of the input and K) will be
   573→obtained.
   574→In keeping with standard terminology in deep learning literature, we will continue to refer to
   575→the cross-correlation operation as a convolution even though, strictly-speaking, it is slightly
   576→different. Furthermore, we use the term element to refer to an entry (or component) of any
   577→tensor representing a layer representation or a convolution kernel.

   579→As described in Section 7.1.4, the convolutional layer output in Fig. 7.2.1 is sometimes
   580→called a feature map, as it can be regarded as the learned representations (features) in the
   581→spatial dimensions (e.g., width and height) to the subsequent layer. In CNNs, for any el-
   582→ement 𝑥of some layer, its receptive field refers to all the elements (from all the previous
   583→layers) that may affect the calculation of 𝑥during the forward propagation. Note that the
   584→receptive field may be larger than the actual size of the input.
   585→Let’s continue to use Fig. 7.2.1 to explain the receptive field. Given the 2 × 2 convolution
   586→kernel, the receptive field of the shaded output element (of value 19) is the four elements
   587→in the shaded portion of the input. Now let’s denote the 2 × 2 output as Y and consider a
   588→deeper CNN with an additional 2×2 convolutional layer that takes Y as its input, outputting
   589→a single element 𝑧. In this case, the receptive field of 𝑧on Y includes all the four elements
   590→of Y, while the receptive field on the input includes all the nine input elements. Thus, when
   591→any element in a feature map needs a larger receptive field to detect input features over a
   592→broader area, we can build a deeper network.

   618→The core computation required for a convolutional layer is a cross-correlation operation.
   619→We saw that a simple nested for-loop is all that is required to compute its value. If we
   620→have multiple input and multiple output channels, we are performing a matrix–matrix op-
   621→eration between channels. As can be seen, the computation is straightforward and, most
   622→importantly, highly local. This affords significant hardware optimization and many recent
   623→results in computer vision are only possible because of that. After all, it means that chip
   624→designers can invest in fast computation rather than memory when it comes to optimizing
   625→for convolutions. While this may not lead to optimal designs for other applications, it does
   626→open the door to ubiquitous and affordable computer vision.
