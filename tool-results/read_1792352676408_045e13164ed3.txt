   557→7.2.5 Cross-Correlation and Convolution
   558→Recall our observation from Section 7.1 of the correspondence between the cross-correlation
   559→and convolution operations. Here let’s continue to consider two-dimensional convolutional
   560→layers. What if such layers perform strict convolution operations as defined in (7.1.6) in-
   561→stead of cross-correlations? In order to obtain the output of the strict convolution operation,
   562→we only need to flip the two-dimensional kernel tensor both horizontally and vertically, and
   563→then perform the cross-correlation operation with the input tensor.
   564→It is noteworthy that since kernels are learned from data in deep learning, the outputs of
   565→convolutional layers remain unaffected no matter such layers perform either the strict con-
   566→volution operations or the cross-correlation operations.
   567→To illustrate this, suppose that a convolutional layer performs cross-correlation and learns
   568→the kernel in Fig. 7.2.1, which is here denoted as the matrix K. Assuming that other con-
   569→ditions remain unchanged, when this layer instead performs strict convolution, the learned
   570→kernel K′ will be the same as K after K′ is flipped both horizontally and vertically. That
   571→is to say, when the convolutional layer performs strict convolution for the input in Fig.
   572→7.2.1 and K′, the same output in Fig. 7.2.1 (cross-correlation of the input and K) will be
   573→obtained.

   575→the cross-correlation operation as a convolution even though, strictly-speaking, it is slightly
   576→different. Furthermore, we use the term element to refer to an entry (or component) of any
   577→tensor representing a layer representation or a convolution kernel.

   799→7.3.3 Summary and Discussion
   800→Padding can increase the height and width of the output. This is often used to give the
   801→output the same height and width as the input to avoid undesirable shrinkage of the output.
   802→Moreover, it ensures that all pixels are used equally frequently. Typically we pick symmetric
   803→padding on both sides of the input height and width. In this case we refer to (𝑝h, 𝑝w)
   804→padding. Most commonly we set 𝑝h = 𝑝w, in which case we simply state that we choose
   805→padding 𝑝.
   806→A similar convention applies to strides. When horizontal stride 𝑠h and vertical stride 𝑠w
   807→match, we simply talk about stride 𝑠. The stride can reduce the resolution of the output, for
   808→example reducing the height and width of the output to only 1/𝑛of the height and width of
   809→the input for 𝑛> 1. By default, the padding is 0 and the stride is 1.
   810→So far all padding that we discussed simply extended images with zeros. This has signif-
   811→icant computational benefit since it is trivial to accomplish. Moreover, operators can be
   812→engineered to take advantage of this padding implicitly without the need to allocate addi-
   813→tional memory. At the same time, it allows CNNs to encode implicit position information
   814→within an image, simply by learning where the “whitespace” is. There are many alternatives
   815→to zero-padding. Alsallakh et al. (2020) provided an extensive overview of those (albeit
   816→without a clear case for when to use nonzero paddings unless artifacts occur).

   941→7.4.3 1 × 1 Convolutional Layer
   942→At first, a 1 × 1 convolution, i.e., 𝑘h = 𝑘w = 1, does not seem to make much sense.
   943→After all, a convolution correlates adjacent pixels. A 1 × 1 convolution obviously does
   944→not. Nonetheless, they are popular operations that are sometimes included in the designs
   945→of complex deep networks (Lin et al., 2013, Szegedy et al., 2017). Let’s see in some detail
   946→what it actually does.
   947→Because the minimum window is used, the 1×1 convolution loses the ability of larger con-
   948→volutional layers to recognize patterns consisting of interactions among adjacent elements
   949→in the height and width dimensions. The only computation of the 1 × 1 convolution occurs
   950→on the channel dimension.
   951→Fig. 7.4.2 shows the cross-correlation computation using the 1×1 convolution kernel with 3
   952→input channels and 2 output channels. Note that the inputs and outputs have the same height
   953→and width. Each element in the output is derived from a linear combination of elements at
   954→the same position in the input image. You could think of the 1 × 1 convolutional layer as
   955→constituting a fully connected layer applied at every single pixel location to transform the
   956→𝑐i corresponding input values into 𝑐o output values. Because this is still a convolutional
   957→layer, the weights are tied across pixel location. Thus the 1 × 1 convolutional layer requires
   958→𝑐o × 𝑐i weights (plus the bias). Also note that convolutional layers are typically followed
   959→by nonlinearities. This ensures that 1 × 1 convolutions cannot simply be folded into other
   960→convolutions.
   961→t
   962→Fig. 7.4.2
   963→The cross-correlation computation uses the 1 × 1 convolution kernel with three input
   964→channels and two output channels. The input and output have the same height and width.
   965→Let’s check whether this works in practice: we implement a 1 × 1 convolution using a fully
   966→connected layer. The only thing is that we need to make some adjustments to the data shape
   967→before and after the matrix multiplication.
   968→def corr2d_multi_in_out_1x1(X, K):
   969→c_i, h, w = X.shape
   970→c_o = K.shape[0]
   971→X = X.reshape((c_i, h * w))
   972→K = K.reshape((c_o, c_i))
   973→# Matrix multiplication in the fully connected layer
   974→Y = torch.matmul(K, X)
   975→return Y.reshape((c_o, h, w))

   988→7.4.4 Discussion
   989→Channels allow us to combine the best of both worlds: MLPs that allow for significant
   990→nonlinearities and convolutions that allow for localized analysis of features. In particular,
   991→channels allow the CNN to reason with multiple features, such as edge and shape detec-
   992→tors at the same time. They also offer a practical trade-off between the drastic parameter
   993→reduction arising from translation invariance and locality, and the need for expressive and
   994→diverse models in computer vision.
   995→Note, though, that this flexibility comes at a price. Given an image of size (ℎ× 𝑤), the cost
   996→for computing a 𝑘× 𝑘convolution is O(ℎ· 𝑤· 𝑘2). For 𝑐i and 𝑐o input and output channels
   997→respectively this increases to O(ℎ· 𝑤· 𝑘2 · 𝑐i · 𝑐o). For a 256 × 256 pixel image with a
   998→5 × 5 kernel and 128 input and output channels respectively this amounts to over 53 billion
   999→operations (we count multiplications and additions separately). Later on we will encounter
  1000→effective strategies to cut down on the cost, e.g., by requiring the channel-wise operations
  1001→to be block-diagonal, leading to architectures such as ResNeXt (Xie et al., 2017).
