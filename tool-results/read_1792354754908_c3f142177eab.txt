   217→  1387→At each time step, the decoder predicts a probability distribution for the output tokens.
   218→  1388→As with language modeling, we can apply softmax to obtain the distribution and calculate
   219→  1389→the cross-entropy loss for optimization. Recall from Section 10.5 that the special padding
   220→  1390→tokens are appended to the end of sequences and so sequences of varying lengths can be
   221→  1391→efficiently loaded in minibatches of the same shape. However, prediction of padding tokens
   222→  1392→should be excluded from loss calculations. To this end, we can mask irrelevant entries
   223→  1393→with zero values so that multiplication of any irrelevant prediction with zero equates to
   224→  1394→zero.

   229→  1399→return (l * mask).sum() / mask.sum()

   389→  1559→10.8 Beam Search
   390→  1560→In Section 10.7, we introduced the encoder–decoder architecture, and the standard tech-
   391→  1561→niques for training them end-to-end. However, when it came to test-time prediction, we
   392→  1562→mentioned only the greedy strategy, where we select at each time step the token given the
   393→  1563→highest predicted probability of coming next, until, at some time step, we find that we have
   394→  1564→predicted the special end-of-sequence “<eos>” token. In this section, we will begin by for-
   395→  1565→malizing this greedy search strategy and identifying some problems that practitioners tend
   396→  1566→to run into. Subsequently, we compare this strategy with two alternatives: exhaustive search
   397→  1567→(illustrative but not practical) and beam search (the standard method in practice).
   398→  1568→Let’s begin by setting up our mathematical notation, borrowing conventions from Section
   399→  1569→10.7. At any time step 𝑡′, the decoder outputs predictions representing the probability of
   400→  1570→each token in the vocabulary coming next in the sequence (the likely value of 𝑦𝑡′+1), con-
   401→  1571→ditioned on the previous tokens 𝑦1, . . . , 𝑦𝑡′ and the context variable c, produced by the
   402→  1572→encoder to represent the input sequence. To quantify computational cost, denote by Y the
   403→  1573→output vocabulary (including the special end-of-sequence token “<eos>”). Let’s also spec-
   404→  1574→ify the maximum number of tokens of an output sequence as 𝑇′. Our goal is to search for
   405→  1575→an ideal output from all O(|Y|𝑇′) possible output sequences. Note that this slightly over-
   406→  1576→estimates the number of distinct outputs because there are no subsequent tokens once the
   407→  1577→“<eos>” token occurs. However, for our purposes, this number roughly captures the size
   408→  1578→of the search space.

   464→  1634→10.8.2 Exhaustive Search
   465→  1635→If the goal is to obtain the most likely sequence, we may consider using exhaustive search:
   466→  1636→enumerate all the possible output sequences with their conditional probabilities, and then
   467→  1637→output the one that scores the highest predicted probability.
   468→  1638→While this would certainly give us what we desire, it would come at a prohibitive com-
   469→  1639→putational cost of O(|Y|𝑇′), exponential in the sequence length and with an enormous
   470→  1640→base given by the vocabulary size. For example, when |Y| = 10000 and 𝑇′ = 10, both
   471→  1641→small numbers when compared with ones in real applications, we will need to evaluate
   472→  1642→1000010 = 1040 sequences, which is already beyond the capabilities of any foreseeable
   473→  1643→computers. On the other hand, the computational cost of greedy search is O(|Y| 𝑇′): mirac-
   474→  1644→ulously cheap but far from optimal. For example, when |Y| = 10000 and 𝑇′ = 10, we only
   475→  1645→need to evaluate 10000 × 10 = 105 sequences.
